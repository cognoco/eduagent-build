**What was done:** Made the single-use guardian verifier redemption durable, replay-safe and recoverable without retaining raw verifier handles, bearer tokens or signing secrets.

**What changed:** Added a constrained guardian-authority redemption receipt keyed by a non-secret handle digest and command binding. A successful verifier result is committed before response, an exact retry reconstructs the same still-valid signed authority, concurrent or mutated retries fail closed, and attachment accepts a token only when its durable issued receipt matches. Transport, timeout, non-success HTTP, malformed-response and pending-provider failures release only the still-redeeming reservation, emit a structured operational event and return a retryable unavailable result; explicit denial or binding mismatch remains terminal. The mobile callback preserves the issued token across attachment retries.

**Verification:** The named real-database regression first reproduced permanent handle consumption after a transport failure and then passed after retryable reservation release. The isolated PostgreSQL suite passed all guardian ceremony cases, including response-loss replay, two-connection contention, mutated tuple rejection, missing receipt rejection, persistence disappearance, provider timeout signalling and same-handle transport recovery. The fresh migration chain through the guardian redemption migration, database schema tests, token tests, mobile retry tests, API typecheck and repository prepush gate are green.

**Caveats / Follow-ups:** Provider selection remains intentionally outside this item. Explicit denials and authority-binding mismatches remain durable terminal outcomes; only failures without an authoritative decision release the local reservation for retry.
